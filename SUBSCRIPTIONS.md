# DeepStats — subscriptions setup (v8)

This branch is a preview. **Do not merge into production until configured and tested.**

## Architecture
- Each subscriber receives a random activation code, generated by the admin API.
- The code is hashed with SHA-256 before storage. The raw code is returned once.
- Login exchanges the code for a signed session (maximum 12 hours).
- Every protected `/api/data` request verifies the session, subscriber status and expiry on the server.
- `APP_ACCESS_TOKEN` remains an **admin-only** secret for compatibility; never distribute it to subscribers.
- Only server-side Supabase service role can access `ds_subscribers`. No client-side database keys.

## One-time setup
1. In your **private** Supabase project, execute `supabase/subscriptions.sql` in SQL editor.
2. Add the following server-side Vercel environment variables for Preview first:
   - `SUPABASE_URL` — your Supabase project URL
   - `SUPABASE_SERVICE_ROLE_KEY` — service role key; **never** expose to frontend
   - `SESSION_SECRET` — independently generated, random 32+ byte secret
3. Keep existing `APP_ACCESS_TOKEN` for admin login, `GOOGLE_CLIENT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `SPREADSHEET_ID`.
4. Deploy the preview branch and verify: admin login, create code, subscriber login, pause, extend, expired account, blocked API request, Android PWA update.
5. Merge only after tests pass.

## Admin flow
Login with your existing private admin token. An admin button appears in the header. Create a subscriber with name and access duration. Copy the newly displayed code immediately. It cannot be recovered later; create a replacement subscriber if lost. Pause/reactivate or extend subscribers from the panel.

## Security and limitations
- The shared admin token should be kept private and rotated if it was ever sent to a client.
- Admin login is a transitional compatibility path; production hardening should move to a separate authenticated admin identity with MFA.
- A subscription code can be shared with others; device/session limits and rate limiting are not implemented yet.
- Rate limiting on login is strongly recommended before distributing access broadly.
- Browser sessions use sessionStorage and expire at most 12 hours after login. Subscribers must log in again.
- Supabase project and billing must be configured by the owner; this branch does not provision infrastructure.
- No payment collection is included. Manual activation only.
